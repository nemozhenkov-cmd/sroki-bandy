# СРОКИ БАНДЫ

PWA для двух магазинов: Видова 163В и Видова 190А.

## Стек
- React + Vite
- Supabase Auth/Postgres/Realtime
- Open Food Facts API для поиска товара по EAN
- PWA через manifest; production service worker можно включить через vite-plugin-pwa.

## Запуск
1. Создайте бесплатный проект Supabase.
2. SQL Editor → выполните `supabase.sql`.
3. Authentication → Email включён. Для первого теста можно отключить Confirm email, затем включить обратно.
4. Скопируйте Project URL и anon key в `.env` по образцу `.env.example`.
5. `npm install`
6. `npm run dev`
7. Для production: `npm run build` и разместить `dist` на Cloudflare Pages / GitHub Pages / Vercel.

## Важно про 0 ₽
Supabase Free не требует платного тарифа для такого небольшого проекта, но имеет квоты. Текущие ограничения: 500 MB DB/project, 50k MAU, 1 GB storage, 5 GB egress и 2 млн realtime messages. При превышении квот нужно контролировать использование; приложение не должно подключать биллинг автоматически.

Open Food Facts имеет rate limit на чтение продукта по IP, поэтому приложение сначала проверяет свою базу.

## Ограничения MVP

### Реальное сканирование
В интерфейсе есть камера через нативный `BarcodeDetector` для EAN-13/EAN-8/UPC-A/UPC-E. На Android Chrome это требует HTTPS и разрешения камеры. Для браузеров без BarcodeDetector нужен ZXing fallback на следующей итерации.
- Полноценный системный push и фоновая отправка уведомлений требуют отдельного сервера/cron/edge-функции. В текущем MVP заложена структура данных, но не имитируется отправка уведомлений.
- Нативный barcode scanner зависит от поддержки браузером BarcodeDetector. Для production рекомендуется подключить библиотеку fallback (например, ZXing) и отдельный экран камеры.
- История и админские RLS-политики требуют дальнейшего усиления: в production роль должна проверяться серверной политикой/функцией, а не только клиентом.
- Offline queue в этой первой сборке не реализована намеренно, чтобы не выдавать демо за полноценную синхронизацию.

## Нумерация публикаций

Номер установленной версии отображается в шапке профиля между логотипом и заголовком, в том числе без интернета. Источник — `version` в `package.json`: значение встраивается при сборке, поэтому старая копия приложения показывает свой номер, а не номер на сервере.

Перед каждой следующей публикацией повышайте номер (`npm version patch --no-git-tag-version` для исправлений; `minor` для новых функций; `major` для несовместимых изменений). Коммитьте `package.json` и `package-lock.json` вместе с изменениями и указывайте номер в сообщении о публикации. Текущая версия — 2.1.0. Внутренний идентификатор сборки для обновления PWA остаётся отдельным.

При сборке Vite автоматически встраивает общий идентификатор сборки в JS и тело `dist/sw.js`. Не публикуйте `public/sw.js` напрямую: неизменный файл worker не позволяет старым копиям обнаружить обновление интерфейса. Регистрация использует стабильный URL; старые URL с `?v=` также получают новый файл. Идентификатор кэша определяется новой сборкой, а не параметром URL старого клиента. Быстрый запуск из кэша сохранён; проверка обновлений выполняется при старте, возвращении к приложению, восстановлении связи и каждую минуту. IndexedDB с очередью не затрагивается.

## Раздельные роли РТЗ / СРТЗ (2.1.0)

Новые профили создаются с ролью `rtz`. Старый клиент с `srtz_rtz` нормализуется сервером в `rtz`; существующие объединённые роли переведены в РТЗ, поскольку старый профиль не фиксировал старшинство.

Управляющий в «Профиль → Сотрудники магазина» выбирает РТЗ / СРТЗ и сохраняет. Изменять можно только сотрудников своего активного магазина. Нельзя менять себя, управляющего, ТМ, администратора, чужой магазин или другие поля профиля. RPC работает с RLS (`SECURITY INVOKER`), триггер проверяет ограничения и при прямом REST-запросе. Администратор сохраняет прежнее управление ролями и магазинами.

При регистрации сервер отклоняет самоназначение СРТЗ/управляющего/администратора. Обе роли сохраняют работу с товарами, рекомендациями, офлайн-очередью и уведомлениями. Роль в локальной копии обновляется после повторной загрузки с интернетом; назначение ролей доступно онлайн. Напоминания о рабочих задачах в этот выпуск не входят.

Проверки: `node --test tests/*.test.mjs`; `tests/staff-roles.sql` запускается транзакционно с откатом учебных профилей и магазинов.
